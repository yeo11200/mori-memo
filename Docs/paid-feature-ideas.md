# MORI 유료 기능 아이데이션과 개발 후보

작성일: 2026-09-15. 상태: 제안. 이 문서는 신규 기능·상품을 검토하기 위한 계획이며 구현 완료, 판매 개시, 가격 확정을 뜻하지 않는다.

후속 결정: 무료 베타를 먼저 배포하고 Pro 구매는 비밀번호 없는 이메일 계정에 연결한다. 같은 계정을 동기화·팀 기능으로 확장하되 각각 별도 개발한다. [계정·결제 개발 계획](account-billing-plan.md)에 사용자 흐름과 완료 기준을 정리했다. 가격과 구매 방식은 아직 미확정이다.

## 제품 방향

첫 메시지는 ‘오늘 일정과 Jira 업무를 데일리 한 장에 모으는 Mac 앱’으로 유지한다. 유료 가치는 모인 기록으로 보고서를 만들고, 회의를 준비하고, 개발 문서를 유지하는 반복 작업에서 만든다.

MORI 앱과 Codex·Claude 스킬은 별도 개발 영역이다. 앱은 지식과 기록을 보관한다. 스킬은 필요한 지식을 찾아 작업에 적용한다. 사용자가 저장을 선택한 초안만 MORI에 넣고 코드 결과나 대화를 자동 저장하지 않는다. 폴더나 저장소 등록을 필수로 만들지 않는다.

기존 기준: [수익화 원칙](marketing-revenue-plan.md), [앱 계획](mori-app-development-plan.md), [AI 스킬 계획](mori-ai-skills-development-plan.md). 보관함에서 ‘수익화’, ‘과금’ 검색으로 관련 메모는 찾지 못했으며 저장소 문서와 이번 대화를 기준으로 작성했다.

## B. Codex·Claude 스킬 및 AI 기능 후보

기본 mori-context 검색·읽기는 무료로 유지하는 안이다. 아래 기능은 기존 스킬에 이미 포함되어 있다는 의미가 아니다.

| ID | 기능 | 사용 흐름 | 상품 후보 / 선행 조건 |
|---|---|---|---|
| B01 | 작업 문맥 묶음 | ‘인증 수정’ 요청에 관련 규칙·설계·결정 기록을 출처와 선택 | Developer 후보 / 범위·길이 제한 |
| B02 | 문서 최신성 검사 | 사용자가 지정한 코드 범위와 문서를 비교해 확인·차이·미확인 표시 | Developer / 코드 접근 동의와 비교 기준 |
| B03 | 문서 수정 제안 | 코드 변경에 따라 수정안을 보여주고 승인한 부분만 반영 | Developer / 수정 충돌 검사·되돌리기 |
| B04 | MSA 문맥 선택 | 공통 규칙·서비스 관계·해당 서비스 문서를 골라 충돌 표시 | Developer / 서비스 식별·우선순위 |

저장소 연결은 코드 비교 작업에서만 선택적으로 사용한다. 일반 문서 검색에 저장소 등록이나 특정 ‘개발 가이드’ 폴더를 강제하지 않는다. 여러 서비스가 검색되면 이름이 비슷하다는 이유로 규칙을 섞지 않는다.

검색 결과만으로 사실을 단정하지 않는다. 코드와 실제 비교하지 않은 문서는 ‘최신’이라고 표시하지 않는다. CLI를 Mac에서 실행하는 것과 오프라인 AI 추론은 구분한다. 현재 검색을 임베딩 RAG로 홍보하지 않는다.

## 첫 유료 기능: 주간 업무보고 상세안

### 화면 흐름

1. 데일리 화면에서 ‘주간보고 만들기’를 선택한다.
2. 기간, 포함할 메모·프로젝트·외부 출처를 선택한다. 폴더 지정 없이도 사용 가능하다.
3. 포함할 자료 수와 AI에 전달될 본문 범위를 확인한다. 연결한 제공자와 비용 발생 가능성을 표시한다.
4. 템플릿을 고른다: 주간보고 / 스탠드업 / 회고. 생성은 버튼으로 실행한다.
5. 초안 옆에 근거 메모·이슈 링크를 표시한다. 사용자가 수정·제외할 수 있다.
6. 복사, Markdown 내보내기 또는 새 MORI 메모 저장을 선택한다. 자동 발송은 하지 않는다.

### 포함 범위와 정확성

- 날짜는 사용자 로컬 시간 기준으로 경계를 표시한다. 일자가 없는 메모는 선택해서 포함한다.
- 첫 버전은 선택한 기간의 MORI 저장 기록을 기준으로 한다. 과거 외부 업무 상태를 현재 API 결과로 재구성하지 않는다.
- ‘개인 체크 완료’와 ‘Jira 원본 완료’를 구분한다. 확인할 수 없는 성과 수치나 시간을 생성하지 않는다.
- 근거가 없는 문장은 빼거나 미확인으로 표시한다. 삭제된 출처는 현재 접근 불가로 보여준다.
- 근거 링크는 앱이 수집한 ID 목록으로 검증한다. 모델이 만든 임의 ID를 링크로 저장하지 않는다.
- 자료가 없으면 빈 상태를 안내한다. 길이 제한을 넘으면 포함 범위를 줄이도록 안내하며 조용히 일부를 누락하지 않는다.
- 취소·실패 시 원문을 바꾸지 않는다. 재시도는 명시적으로 하며 같은 결과의 중복 저장을 막는다.
- AI가 없어도 기간별 원문 목록·기본 템플릿은 사용할 수 있다. AI 생성은 사용자 제공자 연결이 필요하다.

### 개발 작업과 완료 기준

| 작업 | 구현 범위 | 완료 판단 |
|---|---|---|
| 자료 선택 | 기간·출처·문서 ID 기반 수집 | 날짜 경계, 중복, 삭제·빈 자료 처리 |
| 생성 계약 | 섹션·본문·출처 ID를 구조화 | 존재하지 않는 출처 거부, 오류 안내 |
| 초안 화면 | 편집·출처 이동·취소·다시 생성 | 사용자 편집 보호, 키보드 접근 |
| 결과 사용 | 복사·내보내기·새 메모 저장 | 기존 문서 불변, 중복 저장 방지 |
| 제공자 연결 | 기존 AI 실행 경로 활용 | 인증 실패·취소·시간 초과 처리 |
| 권한 적용 | 무료 체험과 Pro 기능 판정 분리 | 만료 후 기존 결과 열기·내보내기 유지 |

자료 선택과 출처 검증은 결정적인 로직으로 테스트하고, 초안의 유용성은 샘플 주간 기록으로 사람이 평가한다. 테스트 수만으로 보고서 품질을 판단하지 않는다.

## 무료·유료 경계와 가격 실험

기존 무료 기능을 갑자기 잠그지 않는다. 메모 작성·검색·링크·기본 그래프·현재 기본 연동·기본 읽기 스킬·내보내기를 유지하는 안이다. 오류 수정, 연결 복구, 데이터 접근을 유료 혜택으로 만들지 않는다.

| 상품 가설 | 포함 후보 | 가격 실험안 | 주의점 |
|---|---|---|---|
| Free | 기존 핵심과 기본 데일리 | 무료 | 지속 사용과 신뢰 기반 |
| Desktop Pro | 주간보고·템플릿·로컬 고급 기능 | 일회성 49,000원 | 구매 버전 사용권과 업데이트 제공 기간을 명시 |
| Pro 구독 대안 | 반복 자동화·지속 개선되는 업무 기능 | 월 4,900원 / 연 49,000원 | 일회성과 동시에 출시하지 않고 선호 비교 |
| Sync | 기기 간 동기화·호스팅 백업 | 비용 검증 뒤 결정 | 서버 비용·복구·운영 책임 선행 |
| Team | 공유 정책·권한·배포·감사 기록 | 팀 인터뷰 뒤 결정 | 개인 앱 안정화 뒤 검증 |

가격은 전부 가설이다. 기존 계획의 로컬 일회성 구매 원칙을 기본으로 두고, 앞선 대화의 구독안은 비교 실험으로 남긴다. 첫 출시에서 Developer·Team 등 여러 플랜을 만들지 않는다. 초기 Pro에 포함해 가치부터 확인한다.

AI는 처음에는 사용자 CLI·API 연결을 활용한다. 앱 구매가 외부 제공자의 이용권을 포함하지 않음을 표시한다. 자체 AI 크레딧 상품은 실제 원가와 실패·재시도 비용을 측정한 뒤 검토하며 ‘무제한’은 약속하지 않는다.

구독 만료 또는 라이선스 확인 실패로 기존 메모와 생성 문서를 잠그지 않는다. 일회성 구매라면 업데이트 기간이 끝나도 구매한 버전을 사용할 수 있어야 한다. 무료 체험 기간·횟수는 판매 전 확정하고 사용자에게 명확히 표시한다.

## 결제 기능 개발 전 필요한 기반

- 판매할 실제 기능과 체험 범위를 먼저 완성한다. 이번 문서가 결제 도입을 실행하는 것은 아니다.
- 결제 사업자, 구매 식별·라이선스 재발급, 기기 변경 정책을 결정한다.
- 결제 결과는 검증된 서버 이벤트로 반영하고 중복 이벤트·환불·취소를 처리한다. 클라이언트 플래그만으로 결제 상태를 신뢰하지 않는다.
- 로컬 앱은 오프라인 사용과 인증 서버 장애에 대한 유예 정책을 둔다. 정확한 기간은 출시 정책에서 확정한다.
- 결제 정보와 메모 보관함을 분리한다. 유료화 때문에 메모 본문을 수집하지 않는다.
- 설치 안내, 서명·공증 여부, 업데이트 경로, 환불·지원 안내를 구매 전에 공개한다. 세금·판매 조건은 실제 판매 지역과 사업자에 맞춰 별도 확인한다.
- 공개 저장소의 현재 라이선스와 유료 배포 모델의 관계를 확인한다. 클라이언트 잠금만으로 복제를 완전히 방지한다고 가정하지 않는다.

## 실행 순서와 검증

### 1차: 사용 기반

A01 미완료 이월과 A02 연결 진단부터 개선한다. 이월은 개인 항목만 대상으로 하고 외부 연동 구역을 복사해 중복하지 않는다. 앱이 닫힌 동안의 예약 실행은 범위 밖이다.

### 2차: 첫 Pro 체험

A03 주간보고와 A04 템플릿을 구현한다. 먼저 과금 없이 초대 사용자에게 시험하고, 실제 사용 가능한 결과와 결제 의사를 따로 확인한다.

제안한 판단 기준: 동의한 사용자 5~10명이 2주 동안 두 차례 보고서를 만들고, 3명 이상이 실제 업무에 사용했다고 확인되면 가격 실험을 진행한다. 이는 목표이며 현재 실적이 아니다. 생성 횟수를 반복 사용이나 구매 의사로 대신하지 않는다.

### 3차: 선택 확장

회의 준비 수요가 많으면 A05, 여러 프로젝트 관리가 어려우면 A07, 개발 문서 유지 요청이 많으면 B02를 다음 작업으로 선택한다. 모두 동시에 개발하지 않는다.

### 4차: 운영 상품

동기화·iPhone·Team은 인증, 충돌, 권한, 운영비 검증 후 별도 계획으로 진행한다.
