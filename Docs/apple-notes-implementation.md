# Apple 메모 연동 · MORI 0.4.0

## 사용 방법

1. 상단 **Apple 메모 연동** 또는 빈 보관함의 **Apple 메모 가져오기**를 누른다.
2. **Apple 메모 목록 읽기**를 누르고 macOS 접근 허용 요청에 응답한다.
3. **폴더·메모 직접 선택**에서 폴더 또는 개별 메모를 선택한다. 검색으로 원하는 항목을 찾을 수 있다.
4. 예상 신규·변경·검토 건수를 확인하고 **가져오기**를 누른다.
5. 다음에는 **연동한 모든 항목**을 선택하고 목록을 새로 읽어 가져온다. 등록한 폴더에 새로 생긴 메모도 포함된다.

읽기 권한이 거부되면 시스템 설정 → 개인정보 보호 및 보안 → 자동화에서 MORI(개발 실행은 Electron 또는 실행 도구)의 메모 접근을 확인한다. 전체 디스크 접근이나 Apple 비공개 DB 직접 읽기는 사용하지 않는다.

## 구현과 데이터 보호

- 설치된 `/System/Applications/Notes.app/Contents/Resources/Notes.sdef`의 계정·폴더·메모 ID·plaintext·password protected·attachment 속성을 JXA로 읽는다.
- Apple 원본을 생성·수정·삭제하는 명령은 없다. 처음 가져온 메모는 Apple의 계정·하위 폴더 경로를 MORI 폴더로 사용한다. 파일 경로에 사용할 수 없는 문자는 `›`로 표시한다(예: `iCloud / 업무` → `iCloud › 업무`). 이후 MORI에서 폴더를 이동하면 다음 동기화에서도 사용자의 MORI 폴더 위치를 유지한다.
- 원본 ID와 출처·콘텐츠 해시를 Markdown 메타데이터에 함께 저장해 반복 실행 중복을 방지한다. 제목이 같은 원본도 ID로 구분한다.
- 원본이 변경되고 MORI 본문은 그대로면 기존 ID의 새 버전으로 저장한다. 백링크와 버전 기록을 유지한다.
- MORI만 수정됐으면 내용을 유지한다. 양쪽이 변경됐을 때 검토 보관함에서 MORI 유지·Apple 반영·직접 편집을 선택한다. 검토 대상은 마지막으로 읽은 원본 스냅샷이다.
- 원본이 목록에 없으면 삭제 또는 계정 접근 상태를 확인하도록 표시하고 MORI 문서는 유지한다. 휴지통에 있는 MORI 메모는 자동으로 재생성하지 않는다.
- 연결 선택·검토 스냅샷·최근 결과는 보관함의 `.wiki/apple-imports.json`에 문서별로 원자 저장한다. 오류가 난 항목은 다음 가져오기에서 재시도할 수 있다.
- 실제 저장 직전에 원본/사본 상태를 다시 비교한다. 편집 중인 메모를 먼저 저장하므로 미저장 내용도 보호한다. 따라서 사전 예상과 결과 건수가 달라질 수 있다.

## 확인한 범위와 제한

- 현재 macOS의 실제 JXA 읽기에 성공했다. 확인 시점에 계정 1개·폴더 1개·메모 0개였으므로 실제 개인 메모 본문 가져오기는 검증할 샘플이 없었다.
- 본문은 일반 텍스트로 가져온다. 사진·PDF·표·서식·체크리스트 완료 상태의 원형 보존은 후속 범위다. 첨부 개수와 미지원 범위를 화면에 알린다.
- 잠긴 메모는 건너뛰고 실패 원인을 표시한다. 일부 항목 실패가 성공 항목 저장을 취소하지 않는다.
- 목록 읽기는 최대 120초·32MB 응답까지 지원한다. 가져오기 전 스냅샷은 5분 동안 유효하며 다시 읽기 실패 시 이전 스냅샷으로 실행하지 않는다.
- 원본 폴더 선택은 해당 폴더의 메모를 대상으로 한다. 하위 폴더는 별도 선택한다. 자동 예약 동기화와 연동 해제 UI는 후속 항목이다.
- AppleScript 자동화 권한을 위한 `NSAppleEventsUsageDescription`을 앱에 포함했다. Developer ID 서명·공증·App Store Sandbox 검증은 별도 배포 단계다.

## 검증 명령

```sh
npm test
npm run package:mac
node scripts/apple-notes-smoke.mjs --packaged
```

앱 테스트는 임시 보관함과 OS 응답 fixture를 사용하되 실제 IPC·비교 서비스·Vault 저장을 통과한다. 원본 Apple 메모에 테스트 데이터를 쓰지 않는다.

검증 완료: 단위 테스트 9개 파일·55개 테스트 통과. 패키징 앱의 Apple 연동 테스트(빈 폴더 연동·선택·실제 저장·출처·미저장 본문 보호·충돌 유지·버전 기록·권한 오류·Escape/포커스)와 기존 편집/검색/모의 AI 회귀 테스트가 통과했다. 패키징된 앱에서 OS 응답 대체 없이 실제 Apple 조회도 성공했으며, 폴더 1개·메모 0개를 확인했다. 실제 사용자 메모 본문에 대한 검증은 메모가 있는 환경에서 후속 확인이 필요하다.

## 계획서 해석

- EventKit을 Notes API로 가정하지 않고 설치된 Notes의 스크립팅 인터페이스를 확인해 선택했다.
- MORI에서만 바뀐 메모는 검토 항목을 늘리지 않고 보존한다. Apple 원본까지 바뀌었을 때 검토가 필요하다.
- AI 스킬 개발은 이 변경에 포함되지 않는다. [앱 계획서](mori-app-development-plan.md)와 [별도 AI 스킬 계획서](mori-ai-skills-development-plan.md)를 구분한다.

Apple 공식 근거: [자동화 접근 사용 목적 설명 키](https://developer.apple.com/documentation/bundleresources/information-property-list/nsappleeventsusagedescription).
