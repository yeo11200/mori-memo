# 주간보고와 맞춤 템플릿

2026-10-20 구현. 기본 빌드는 제한 없는 무료 베타다. 후속으로 상용 빌드의 계정·14일 체험·Pro 권한과 월 결제 코드를 추가했다. [계정·결제 구현과 운영 연결 상태](billing-implementation.md)를 참고한다.

## 사용법

1. 왼쪽 **주간보고 만들기**를 누른다.
2. 시작일·종료일과 폴더·검색으로 자료를 찾고 사용할 기록을 선택한다. 데일리는 기록 날짜, 일반 메모는 마지막 수정일을 기준으로 찾는다. 날짜가 없거나 기간 밖인 자료는 **기간 밖 기록도 직접 선택하기**로 찾는다.
3. **전달할 본문 확인**과 선택한 전체 자료 목록으로 포함 범위를 확인한다. 최대 30개, 제목·본문 합계 80,000자이며 초과분을 자동으로 자르지 않는다.
4. 주간보고·스탠드업·회고 양식을 고른다. **맞춤 템플릿 만들기**에서 이름·항목·말투를 저장하고 재사용할 수 있다. 맞춤 템플릿은 최대 20개이며 항목은 1~8개다. 수정·삭제도 지원한다.
5. **원문 모음 만들기**는 AI 없이 양식과 선택한 원문을 모은다. **AI로 보고서 생성**은 기존 설정의 Codex CLI·Claude CLI·OpenAI API를 사용한다. 선택한 기록의 ID·날짜·제목·본문과 양식을 제공자에 전달하며, 외부 이용료가 발생할 수 있다.
6. 초안을 편집하고 근거 기록을 열어 현재 원문을 읽는다. **보고서 복사**, **Markdown 내보내기**, **새 메모로 저장** 중 선택한다. 저장 위치는 `업무보고` 폴더다.

## 데이터와 동작

- 선택한 기록의 현재 본문 전체를 사용한다. 기간 당시의 Jira·일정 상태를 외부 API에서 재구성하지 않는다. 실제 성과와 개인 체크 완료 여부는 사용자가 확인해야 한다.
- 자료 선택 시점의 revision과 생성 시작 시점의 revision을 비교한다. 변경·삭제된 자료가 있으면 재선택을 요청한다. **자료 새로 선택**으로 현재 목록을 반영한다.
- AI 응답은 항목·문장·출처 ID를 가진 JSON이어야 한다. 양식과 다른 항목, 근거 ID가 없는 문장, 선택하지 않은 ID, 임의 링크는 오류로 처리한다. 실제 위키 링크는 앱이 선택된 자료 ID로 만든다. 이는 문장 의미의 정확성 검증을 대체하지 않는다.
- 생성 후 원문이 바뀌거나 없어지면 근거 목록에 상태를 표시한다. 원문 보기에는 현재 본문을 표시한다.
- 생성·실패·취소는 원본 메모를 수정하지 않는다. AI 결과도 저장 버튼을 누르기 전에는 새 메모로 저장하지 않는다. 저장 중복 요청은 같은 결과에 대해 하나의 메모만 만든다.
- 초안은 앱 실행 중 임시로 유지되며 창을 닫으면 화면의 미저장 편집 내용은 사라진다. 앱을 다시 실행하면 미저장 초안을 복원하지 않는다. 저장된 메모와 내보낸 파일은 계속 사용할 수 있다.
- 맞춤 템플릿은 보관함의 `.wiki/report-templates.json`에 로컬로 저장한다. 기본 AI 연결과 동일하게 로컬 CLI 실행이 오프라인 추론을 뜻하지는 않는다.

## 검증

```sh
npm test
npm run build
node scripts/report-smoke.mjs
```

단위 테스트는 날짜 기준, 원문 변경·삭제·크기 제한, 선택하지 않은 자료의 제외, 잘못된 AI 출처, 실패·취소 후 재시도, 원문 보존, 중복 저장, 템플릿 재시작 후 복원을 확인한다. Electron 스모크는 임시 보관함과 가짜 CLI로 템플릿 저장, 생성 취소·재시도, 근거 열기, 편집·복사·파일 내보내기·새 메모 저장과 로컬 원문 모음을 확인한다.

실제 제공자의 모델별 보고서 품질과 사용자의 반복 사용·구매 의향은 별도 검증이 필요하다. 이번 구현은 결제 전환이나 유료 상품 출시를 의미하지 않는다.
