# MORI 무료 배포·마케팅·수익화 계획

> 0.8.0의 실제 홍보 일정과 채널별 게시글은 [첫 홍보 실행안](marketing/README.md)을 참고하세요. 현재 다운로드는 홈페이지의 버전별 Google Drive 링크를 사용하며, 아래의 초기 배포 채널 제안보다 현재 실행안을 우선합니다.

작성일: 2026-09-09 · 적용 버전: 0.4.0 이후

## 1. 결정 사항

MORI는 먼저 **Apple Silicon용 무료 공개 베타**로 배포한다. Apple Developer Program에는 당장 가입하지 않으며, Developer ID 서명과 Apple 공증도 이번 단계에는 포함하지 않는다. 사용자는 홈페이지에서 DMG를 내려받고 macOS의 확인 절차를 거쳐 설치한다.

초기 사용자는 다음 두 집단을 함께 대상으로 삼는다.

1. Apple 메모를 오래 썼지만 내용이 흩어져 다시 찾기 어려운 사람
2. 프로젝트 문서와 코드 기준을 Codex·Claude가 먼저 읽게 하고 싶은 개발자

두 집단에 서로 다른 제품처럼 말하지 않는다. 공통 약속은 **“흩어진 메모를 연결된 지식으로 만들고, 필요할 때 사람과 AI가 함께 사용한다”**이다. 홈페이지에서는 이 약속 아래 두 개의 시작 경로를 제공한다.

- **Apple 메모를 연결된 개인 위키로**: Apple 메모 가져오기, Markdown 정리, 검색, 문서 링크와 그래프를 보여준다.
- **MORI 문서를 AI의 작업 기준으로**: 코드 컨벤션·아키텍처·개발 문서를 Codex·Claude가 작업 전에 읽는 흐름을 보여준다.

## 2. 제품과 AI 스킬의 경계

두 개발 항목을 명확히 구분한다.

### MORI 앱

- Apple 메모에서 MORI로 단방향 가져오기
- 로컬 Markdown 문서 작성과 보관
- 폴더, 검색, `[[문서 링크]]`, 백링크, 지식 그래프
- 사용자가 요청할 때 실행하는 AI 작성·요약·정리
- 사용자의 로컬 보관함이 지식의 원본

### Codex·Claude AI 스킬

- MORI 문서를 찾아 프로젝트의 기준 문맥으로 제공
- 코드 작업 전에 컨벤션·아키텍처·결정 기록을 우선 확인
- 개발 문서가 없으면 코드 분석 후 “개발 문서부터 작성할까요?”라고 제안
- 사용자가 승인했을 때만 새 문서를 MORI에 저장
- 앱과 별도로 설치·버전 관리하며 Codex와 Claude 각각의 실행 규칙을 제공

MORI 앱은 저장소와 직접 결합되지 않는다. AI 스킬이 프로젝트와 MORI 보관함 사이에서 필요한 문서를 선택해 읽는다. MSA처럼 저장소가 여러 개인 경우에도 서비스별 문서, 공통 규칙, 조직 규칙의 우선순위를 스킬이 분석한다.

## 3. 무료 공개 베타 배포

### 배포 채널

- **기본 다운로드**: GitHub Releases
- **소개 홈페이지**: 다운로드 버튼을 GitHub Release의 고정된 버전 자산으로 연결
- **보조 미러**: Google Drive는 GitHub 장애나 다운로드 접근 문제를 위한 선택 항목으로만 사용
- **소스 코드**: GitHub 저장소에서 공개

Google Drive만 기본 채널로 쓰면 버전, 체크섬, 변경 내역과 이전 릴리스를 함께 관리하기 어렵다. GitHub Releases를 원본으로 두고 홈페이지가 사용자가 이해하기 쉬운 입구 역할을 맡는다.

### 릴리스에 반드시 포함할 정보

- MORI 버전과 릴리스 날짜
- `MORI-x.y.z-arm64.dmg`
- 지원 CPU: Apple Silicon
- 실제 테스트로 확정한 최소 macOS 버전
- SHA-256 체크섬
- 주요 변경 내역과 알려진 문제
- 서명·공증되지 않은 공개 베타라는 설명
- 설치 방법, 삭제 방법, 데이터 보관 위치와 백업 방법
- Apple 메모·화면 캡처 등 권한을 요청하는 이유

최소 macOS 버전은 추측해 표시하지 않는다. 깨끗한 테스트 환경에서 설치와 핵심 기능을 확인한 뒤 릴리스 페이지에 확정한다.

### 설치 안내 원칙

서명되지 않은 앱은 Gatekeeper 경고가 나타날 수 있다. 홈페이지와 릴리스 페이지에서 다음 흐름을 화면과 함께 설명한다.

1. DMG를 열고 MORI를 응용 프로그램 폴더로 옮긴다.
2. Finder의 응용 프로그램에서 MORI를 Control-클릭한 뒤 **열기**를 선택한다.
3. 그래도 차단되면 **시스템 설정 → 개인정보 보호 및 보안**에서 차단 내용을 확인하고 사용자가 직접 열기를 승인한다.

Gatekeeper를 전체 해제하는 터미널 명령은 안내하지 않는다. 앱을 서명·공증한 것처럼 표현하지 않으며, 사용자가 이 제한을 다운로드 전에 알 수 있게 한다.

Apple의 현재 안내에 따르면 Developer ID와 Mac 앱 공증은 Apple Developer Program 혜택이고 멤버십은 연 99달러 또는 지역 통화로 청구된다. 공식 자료: [멤버십 비교](https://developer.apple.com/support/compare-memberships/), [Developer ID](https://developer.apple.com/developer-id/), [Mac 앱 배포](https://developer.apple.com/documentation/technologyoverviews/distribution).

## 4. 홈페이지 구성

### 첫 화면

- 제목: **생각을 모으고, 지식을 연결하다. MORI**
- 설명: **Apple 메모와 Markdown 문서를 내 맥에 보관하고, 링크와 AI로 다시 활용하는 로컬 개인 위키**
- 기본 버튼: **Apple Silicon용 무료 베타 다운로드**
- 보조 버튼: **GitHub에서 보기**
- 버튼 가까이에 `무료 · 로컬 저장 · 현재 서명/공증 전 베타`를 표시

### 이어지는 순서

1. Apple 메모 → MORI → 연결 그래프가 되는 짧은 데모
2. 일반 사용자와 개발자를 위한 두 개의 시작 경로
3. 검색, Markdown, 링크, 그래프, AI 작성 기능
4. “메모 내용은 기본적으로 내 맥에 남습니다”라는 개인정보 설명
5. 설치 3단계와 Gatekeeper 안내
6. 현재 한계: Apple Silicon 전용, 서명 전 베타, Apple 메모의 첨부·표 미지원
7. 변경 내역, GitHub Issues와 의견 보내기

첫 화면에서 기능을 모두 설명하지 않는다. 사용자가 “내 메모가 연결되고 다시 쓰인다”를 먼저 이해한 다음 개발자 활용법을 선택하게 한다.

## 5. 마케팅 실행 계획

### 핵심 데모 두 개

- **일반 사용자 데모**: Apple 메모 여러 개 선택 → MORI 가져오기 → `[[링크]]` 추가 → 그래프에서 관계 확인
- **개발자 데모**: MORI의 코드 컨벤션 문서 → Codex·Claude가 먼저 읽음 → 규칙을 지킨 코드 또는 개발 문서 제안

각 데모는 30~60초 영상, GIF, 긴 사용기 한 편으로 재사용한다. 기능 목록보다 실제 전후 변화를 보여준다.

### 초기 채널

- GitHub README와 Releases
- 개인 블로그와 개발 회고
- X, Threads, LinkedIn 등 현재 운영 중인 채널
- 국내 개발자 커뮤니티와 생산성 도구 커뮤니티
- 짧은 데모 영상과 YouTube Shorts

초기에는 광고비를 쓰지 않는다. 설치가 번거로운 서명 전 베타에서 광고로 방문자를 늘리면 이탈 원인을 학습하기 어렵다. 먼저 제작 과정, Apple 메모 연동 구현기, 로컬 AI 문맥 활용법을 공개해 관심 사용자를 모은다. 영어 설치 안내와 안정 버전이 준비되면 Product Hunt, Hacker News, Reddit 공개를 검토한다.

### 콘텐츠 주제

- “Apple 메모 100개를 연결된 위키로 바꾸기”
- “옵시디언처럼 연결하되 Apple 메모를 버리지 않는 방법”
- “Codex가 코드를 쓰기 전에 내 개발 규칙을 읽게 하기”
- “MORI를 만들며 결정한 로컬 우선 데이터 원칙”
- “서명되지 않은 Mac 앱을 투명하게 베타 배포한 기록”

MORI를 범용 메모 앱이나 Obsidian의 완전한 대체품으로 홍보하지 않는다. Apple 메모에서 시작할 수 있고 동일한 지식을 AI 작업 문맥으로 쓸 수 있다는 조합에 집중한다.

## 6. 개인정보와 측정 원칙

- 메모 본문, 제목, AI 프롬프트를 마케팅 분석 서버로 보내지 않는다.
- 앱에 숨은 사용 추적을 넣지 않는다.
- 홈페이지 방문과 다운로드 버튼 클릭은 개인정보를 최소화한 집계만 사용한다.
- 실제 다운로드 수는 GitHub Releases 통계로 확인한다.
- 제품 사용 경험은 앱 내 선택형 의견 보내기, GitHub Issues, 짧은 인터뷰로 수집한다.
- 분석이나 오류 보고를 앱에 추가할 때는 수집 항목을 먼저 공개하고 사용자가 동의할 때만 켠다.

초기 지표는 다음과 같다.

| 지표 | 확인 방법 | 판단에 쓰는 이유 |
|---|---|---|
| 홈페이지 → 다운로드 전환 | 개인정보 최소 웹 집계 | 메시지가 이해되는지 확인 |
| 릴리스 다운로드 수 | GitHub Releases | 실제 설치 관심 확인 |
| 설치 성공·실패 | 선택형 설문/이슈 | Gatekeeper와 권한 마찰 확인 |
| Apple 메모 가져오기 만족도 | 인터뷰/설문 | 첫 핵심 가치 검증 |
| AI 스킬 대기 수요 | 대기 목록/이슈 반응 | 개발자 경로 우선순위 결정 |
| 다시 사용하는 이유 | 1주 후 선택형 인터뷰 | 반복 사용 가치를 정성 검증 |

앱 사용자를 자동으로 추적하지 않으므로 `활성 사용자`처럼 측정할 수 없는 숫자를 성공 지표로 약속하지 않는다.

## 7. 수익화 원칙과 상품 가설

### 계속 무료로 제공할 핵심

- 로컬 Markdown 작성과 보관
- 검색, 폴더, 문서 링크와 기본 그래프
- Apple 메모 기본 가져오기
- 기본 Codex·Claude 읽기 스킬
- 데이터 내보내기와 백업 가능성

무료 핵심은 MORI를 신뢰하고 지식을 쌓게 하는 기반이다. 특히 기본 AI 스킬을 유료로 막으면 문서를 만들수록 AI 활용이 좋아지는 성장 흐름이 약해진다.

### 일회성 Desktop Pro 후보

- 고급 검색과 대규모 보관함 인덱싱
- 반복 자동화, 일괄 가져오기 규칙, 고급 템플릿
- 그래프 분석과 고급 시각화
- 맞춤 테마와 생산성 도구 연동
- 장기 로컬 버전 기록과 복구 도구

가격은 기능이 검증된 뒤 `39,000원 / 59,000원 / 79,000원` 가설로 결제 의향을 조사한다. 현재는 가격을 확정하거나 선결제를 받지 않는다.

### 구독 후보

구독은 매달 운영비와 지속 가치가 있는 기능에만 적용한다.

- 종단간 암호화 다중 기기 동기화
- iPhone 앱과 Mac 사이의 안정적인 동기화
- 암호화 백업과 버전 복구
- 선택형 호스팅 AI 기능

로컬 편집 기능만으로 월 구독을 요구하지 않는다. 시장 참고로 Obsidian도 로컬 앱의 핵심은 무료로 제공하고 Sync와 Publish 같은 운영 서비스에 별도 요금을 받는다. 현재 가격은 [Obsidian 공식 가격](https://obsidian.md/pricing)에서 확인하며, MORI 가격은 자체 비용과 사용자 검증을 기준으로 별도 결정한다.

### 팀·개발 조직 후보

- 팀 공통 컨벤션과 아키텍처 문서 배포
- MSA 서비스별 문맥과 조직 공통 규칙의 우선순위 관리
- 문서 변경 검토, 역할, 감사 기록
- 신규 개발자 온보딩과 지원
- 사내 환경 설치와 유지보수 계약

AI 개발자 팩은 개인용 기본 읽기 스킬을 무료로 두고, 여러 저장소 자동 분석, 팀 정책, 문서 최신성 검사, 조직 배포를 유료 후보로 검증한다.

광고를 넣거나 메모·행동 데이터를 판매하는 방식은 수익 모델에서 제외한다.

## 8. 단계별 실행과 전환 기준

### 0단계 — 무료 공개 베타 준비

- [ ] Apple Silicon DMG 생성
- [ ] 임시 사용자 계정 또는 깨끗한 맥에서 설치 검증
- [ ] 체크섬, 최소 macOS 버전, 알려진 문제 확정
- [ ] GitHub Release와 설치 안내 작성
- [ ] 한 페이지 홈페이지와 두 핵심 데모 제작
- [ ] 개인정보 설명과 의견 접수 채널 공개

### 1단계 — 핵심 가치 검증

- [ ] Apple 메모 사용자와 개발자 각각 5명 이상 인터뷰
- [ ] 설치 실패 원인과 가져오기 실패 원인을 기록
- [ ] 두 데모 중 다운로드와 피드백으로 이어지는 경로 비교
- [ ] 반복 요청이 많은 기능 세 가지를 다음 로드맵에 반영

`릴리스 누적 다운로드 100회` 또는 `설치 후 다시 사용했다고 확인한 사용자 20명` 중 하나를 달성하면 Developer ID 서명·공증 비용 지출을 검토한다. 이 수치는 성공 보장이 아니라 초기 판단 기준이며, Gatekeeper 때문에 가치 검증 자체가 막히면 더 일찍 가입할 수 있다.

### 2단계 — 신뢰와 유료 수요 검증

- [ ] Apple Developer Program 가입 여부 결정
- [ ] Developer ID 서명, hardened runtime, 공증, 설치 회귀 테스트
- [ ] Desktop Pro 후보 기능의 대기 목록과 가격 인터뷰
- [ ] 기본 AI 스킬 공개와 고급 자동화 수요 확인

### 3단계 — 반복 매출 제품

- [ ] 동기화·iPhone의 기술 비용과 개인정보 설계 확정

## 9. 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|

## 10. 바로 실행할 작업 순서

1. 현재 0.4.0을 배포 후보로 패키징하고 깨끗한 환경에서 설치한다.
2. 최소 macOS 버전, 권한 동작, Codex·Claude CLI 의존성을 확인한다.
3. GitHub Release 초안에 DMG, SHA-256, 설치법, 한계, 변경 내역을 준비한다.
4. 두 경로를 가진 한 페이지 홈페이지와 30~60초 데모 두 개를 만든다.
5. 무료 베타를 작은 사용자 그룹에 먼저 공개하고 설치·첫 가져오기 경험을 고친다.
6. 공개 범위를 넓히면서 AI 스킬의 기본 읽기 흐름을 별도 프로젝트로 구현한다.
7. 측정 가능한 반응을 바탕으로 서명·공증, Desktop Pro, 동기화 순서를 결정한다.

이 문서는 시장 반응에 따라 갱신한다. 다운로드 수만으로 수익화를 서두르지 않고, 사용자가 메모를 다시 찾고 AI 작업에도 반복해서 활용하는지 확인하는 것을 우선한다.
