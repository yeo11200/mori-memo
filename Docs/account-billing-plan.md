# 이메일 계정·Pro 구매·동기화 확장 계획

작성일: 2026-09-15. 상태: 개발 계획. 계정·결제·동기화가 구현되거나 판매가 시작되었다는 의미는 아니다.

## 확정한 제품 방향

- 먼저 무료 베타를 배포하고 반복 사용을 확인한 뒤 Pro를 출시한다.
- 무료 로컬 메모는 가입·로그인 없이 사용한다.
- Pro는 비밀번호 없는 이메일 인증으로 로그인하고 구매 내역을 계정에 연결한다. 별도 라이선스 키 입력은 기본 흐름으로 채택하지 않는다.
- 이메일 인증은 최초 계정 생성과 재로그인을 함께 처리한다. 별도 가입 폼은 필수가 아니다.
- 같은 계정을 향후 Mac·iPhone 동기화와 팀 초대에 사용한다. 로그인 도입만으로 이 기능들이 제공되는 것은 아니다.
- 결제 방식·가격·서비스 사업자는 미확정이다. 일회성 구매와 구독을 모두 지원할 수 있게 개념을 분리하되 첫 출시에서는 한 상품으로 시작한다.

관련 문서: [유료 기능 후보](paid-feature-ideas.md), [수익화 원칙](marketing-revenue-plan.md).

## 단계별 사용자 흐름

### 무료 사용

앱 설치 → 보관함 열기 또는 생성 → 메모·기존 무료 기능 사용. 시작 화면에서 계정 생성을 강요하지 않는다. 로그인하지 않아도 기본 작성·검색·내보내기가 가능하다.

### 이메일 로그인과 구매

1. 설정의 ‘계정 및 Pro’ 또는 Pro 기능 안내에서 이메일 로그인을 선택한다.
2. 이메일 입력 → 일회용 인증 코드 확인 → 최초 사용자는 내부 계정 생성, 기존 사용자는 같은 계정으로 로그인한다.
3. 상품·가격·갱신 조건·AI 비용 포함 여부를 확인하고 결제를 선택한다.
4. 서버가 로그인된 사용자 ID에 연결된 결제 세션을 만든다. 브라우저의 결제 화면에서 진행한다.
5. 결제 완료 후 앱은 ‘구매 확인 중’을 표시한다. 검증된 결제 이벤트로 서버 권한이 갱신되면 Pro를 활성화한다.
6. 새 Mac에서는 같은 이메일로 로그인해 구매를 복원한다. 메모 이동은 별도이며 계정 로그인만으로 로컬 보관함이 복사되지 않는다.

초기 인증 UX는 코드 입력안을 권장한다. 이메일 링크 방식은 브라우저에서 앱으로 돌아오는 처리까지 비교한 뒤 선택할 수 있다. 인증 제공자·SDK와 실제 계약은 구현 착수 시 공식 문서를 확인해 확정한다.

### 향후 동기화와 팀

- 동기화: 로그인 → 대상 보관함과 저장 범위 확인 → 명시적으로 활성화 → 다른 기기 연결.
- 팀: 로그인 → 초대 수락 → 팀 공간 접근. 개인 보관함을 자동 공유하지 않는다.
- 로그인·결제 동의는 메모 업로드 동의가 아니다. 계정만 사용하는 단계에서는 본문을 서버로 보내지 않는다.

## 계정과 권한 모델

아래는 논리 모델이며 확정된 DB 스키마나 API 명세가 아니다.

| 개념 | 역할과 규칙 |
|---|---|
| User | 변경되지 않는 내부 userId. 이메일 대신 구매·권한의 기준으로 사용 |
| AuthIdentity | 인증 제공자 subject와 userId 연결. 검증된 이메일과 변경 상태 관리 |
| Purchase | 결제 사업자 거래 ID, userId, 상품, 상태. 이메일 문자열로 구매를 매칭하지 않음 |
| Entitlement | 사용 가능한 기능·기간·상태. 결제 레코드와 분리해 판정 |
| DeviceSession | 기기별 세션과 철회 상태. 구매 가능한 기기 수는 출시 정책으로 결정 |
| BillingEvent | 외부 이벤트 ID와 처리 결과. 중복·재시도 처리의 기준 |
| Workspace (후속) | 개인·팀 공간의 소유와 접근 경계 |
| Membership (후속) | 사용자와 팀의 역할·접근 범위 |

이메일 변경은 재인증과 새 주소 확인 후 처리하고 userId·구매 내역은 유지한다. 서로 다른 인증 계정을 같은 이메일이라는 이유로 자동 병합하지 않는다. 이메일 분실 시 복구 정책과 지원 절차가 필요하다.

## 앱과 서버의 역할

앱은 로컬 메모·편집·제공자 실행·권한 표시를 담당한다. 서버 또는 관리형 서비스는 인증, 구매 세션, 검증된 결제 이벤트, 권한 조회, 세션 철회를 담당한다. 카드 정보는 결제 사업자 화면에서 처리하며 앱·보관함에 저장하지 않는다.

서버 기능 단위는 인증 요청/확인, 내 권한 조회, 결제 세션 생성, 결제 이벤트 수신, 구매 관리, 세션 철회로 나눈다. 사용자 ID는 요청 본문을 신뢰하지 않고 인증 세션에서 결정한다. 서비스 간 비밀키와 결제 이벤트 검증은 서버에 둔다.

이메일 코드는 짧은 만료 시간·일회 사용·요청 및 검증 횟수 제한을 둔다. 코드와 토큰을 로그에 남기지 않는다. 기기 세션은 OS 보안 저장소를 활용하고 메모와 분리한다.

## 구매 상태와 예외 처리

| 상황 | 예상 동작 |
|---|---|
| 결제 취소·실패 | 무료 기능 유지, 다시 시도 안내 |
| 결제 성공 화면만 도착 | 서버 확인 전 Pro를 활성화하지 않고 확인 중 표시 |
| 이벤트 지연 | 권한 재조회·구매 복원 제공, 재결제부터 유도하지 않음 |
| 이벤트 중복·순서 역전 | 이벤트 ID로 중복 처리 방지, 최신 유효 상태를 확인해 반영 |
| 환불·결제 취소 반영 | 계약에 따른 신규 Pro 실행 권한 조정, 기존 메모는 유지 |
| 구독 갱신 중단 | 이미 결제한 이용 기간까지 권한 유지, 이후 무료 기능으로 전환 |
| 일회성 구매 | 구매 버전 사용권과 업데이트 제공 기간을 구분 |
| 로그인 만료 | 무료 작업은 계속하고 재인증 안내 |
| 서버 장애·오프라인 | 마지막 검증 권한을 제한된 유예 정책으로 활용. 신규 활성화는 온라인 확인 필요 |
| 로그아웃·계정 변경 | 이전 계정의 Pro 권한 캐시 분리·해제, 로컬 메모는 삭제하지 않음 |
| 계정 삭제 | 구독 정리·권한 영향·서버 데이터 처리 범위를 먼저 안내. 로컬 파일은 자동 삭제하지 않음 |

권한 캐시는 위변조와 만료를 검증할 수 있어야 한다. 오프라인 유예 기간과 재확인 주기는 출시 전 확정한다. 네트워크 장애로 기존 문서 열기·편집·내보내기를 막지 않는다. 공개 클라이언트에서 무단 사용을 완전히 방지한다고 가정하지 않는다.

## 설정 화면 제안

- 로그인 전: ‘무료로 사용 중’ / ‘이메일로 로그인’ / Pro 기능 설명.
- 로그인 후: 이메일, 사용 상품, 이용 상태, 구매 복원, 계정·결제 관리, 로그아웃.
- 별도 영역: ‘AI 연결’. MORI Pro 구매와 Codex·Claude·원격 API 이용권을 혼동하지 않도록 설명한다.
- 동기화와 팀 기능은 출시 전까지 사용 가능한 기능처럼 표시하지 않는다.
- 가격 안내에서 기존 데이터 접근, 외부 AI 비용, 갱신·환불 조건을 확인할 수 있게 한다.

## 후속 확장에 필요한 별도 개발

| 단계 | 추가로 필요한 것 | 진입 기준 |
|---|---|---|
| Mac·iPhone 동기화 | 클라우드 저장, 암호화·키 복구, 문서 버전·충돌 병합, 삭제 전파·복구, 첨부 동기화, 오프라인 큐 | 실제 다중 기기 수요와 운영비 확인 |
| 팀 공간 | 서버 권한 검사, 초대·철회, 개인/팀 분리, 역할·감사 기록, 데이터 소유·탈퇴 처리 | 팀 사용 사례와 관리 책임 검증 |
| 팀 AI 스킬 | 허용된 문서만 검색, 결과 권한 검증, 규칙 버전·출처 추적 | 팀 권한 모델이 먼저 동작 |

MORI 계정과 연결 외부 서비스의 계정은 다르다. MORI에 로그인했다고 Google Calendar·Jira 인증을 대체하거나 그 토큰을 자동 동기화하지 않는다.

## 개발 순서와 완료 기준

1. 무료 베타와 첫 Pro 기능의 실제 사용을 검증한다. 무료 기능을 뒤늦게 잠그지 않는다.
2. 인증·결제 사업자, 판매 지역·조건, 구매 방식, 개인정보 보관 범위, 기기·오프라인 정책을 확정한다.
3. 테스트 환경에서 이메일 로그인과 userId 기반 권한을 구현한다. 이메일 변경 뒤에도 동일 구매를 복원하는지 확인한다.
4. 결제 테스트 모드로 성공·실패·지연·중복 이벤트·환불·구독 만료 시나리오를 검증한다.
5. 앱의 Pro 권한을 연결한다. 로그아웃·다른 계정 로그인·오프라인·세션 만료 시 권한 누출과 데이터 잠금이 없는지 확인한다.
6. 깨끗한 Mac 설치, 새 기기 구매 복원, 지원·환불 흐름까지 확인한 뒤 실결제를 연다.
7. 동기화와 팀은 별도 계획·구현·검증 후 출시한다.

완료 판단에는 신규/기존 사용자 인증, 코드 재사용·만료·횟수 제한, 다른 사용자의 구매 접근 차단, 결제 이벤트 검증, 중복 처리, 계정 변경, 권한 종료 뒤 원문 보존을 포함한다. 실제 과금 전 테스트 모드 결과와 설치 안내를 검토한다.

## 남은 결정

- 인증·결제 제공자와 서버 운영 방식
- 일회성/구독 선택과 가격, 체험 조건
- 기기 수와 이전·분실 복구 정책
- 오프라인 유예·계정 삭제·환불 정책
- 데이터 보관·지원 범위와 판매 지역별 요구사항

위 사항은 현 시점에 확정한 것처럼 UI나 홍보에 약속하지 않는다. 이번 결정은 ‘가입 없는 무료 사용 → 이메일 계정 기반 Pro → 같은 계정으로 동기화·팀 확장’이다.
