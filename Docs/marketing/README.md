# MORI 0.8.0 첫 홍보 실행안

현재 목표는 다운로드 수를 크게 만드는 것보다, Apple Silicon Mac 사용자에게 첫 데일리를 만들어 보게 하고 다음 날에도 쓰는지 확인하는 것이다. 아래 수치와 일정은 실행 제안이며 달성된 실적이 아니다.

## 게시할 글

- [Threads: 첫 소개와 후속 게시글](threads.md)
- [LinkedIn: 개발 동기와 업무 흐름](linkedin.md)
- [벨로그: 제품 소개와 개발 기록](velog.md)

각 문서의 ‘게시 본문’ 부분을 복사해 사용한다. 운영 메모는 게시하지 않는다. 실제 게시, 댓글 작성, 메시지 발송은 이 작업에서 수행하지 않았다.

## 한 문장으로 소개하기

**오늘 일정과 Jira 업무를 데일리 한 장에 모으는 Mac용 로컬 메모 앱, MORI.**

대상은 Google Calendar와 Jira를 쓰고, 오늘 할 일과 회의 기록을 메모에 따로 정리하는 개발자·기획자다. 최초 사용 과제는 ‘데일리 한 장 만들기’로 좁힌다. AI 스킬과 지식 그래프는 두 번째 사용 경험으로 소개한다.

## 채널마다 다른 역할

| 채널 | 첫 문장의 역할 | 본문 중심 | 원하는 다음 행동 |
| --- | --- | --- | --- |
| Threads | 여러 앱을 오가는 불편에 공감 | 짧은 제작 이야기와 구체적인 질문 | 자신의 정리 방법 공유, 관심 있으면 체험 |
| LinkedIn | 어떤 업무 문제를 해결했는지 설명 | 만든 이유, 사용 흐름, 설계 원칙 | 업무에 맞는지 판단하고 무료 베타 체험 |
| 벨로그 | 개발자가 배울 주제를 제시 | 로컬 Markdown, 갱신·충돌·체크 보존 설계 | 구현 이해, 소스 확인, 직접 사용 |

같은 글을 세 곳에 복사하지 않는다. 동일한 제품 사실을 서로 다른 독자의 관점에서 설명한다. 유료 광고는 초기 사용자 경험을 확인한 다음 판단한다.

## 2주 실행 일정

D1은 실제 홍보를 시작하는 날이다. 시간은 게시 직후 답변할 수 있는 시간대로 선택한다. 특정 시간대의 노출 우위를 가정하지 않는다.

| 시점 | 실행 | 확인할 질문 |
| --- | --- | --- |
| D1 | 벨로그 글 게시, Threads 첫 소개 게시 | 제품이 무슨 일을 하는지 이해하는가 |
| D2 | LinkedIn 소개 게시 | 어떤 직무와 업무 상황에서 관심을 보이는가 |
| D3 | Threads 후속 1: 데일리 사용 장면 | 첫 데일리를 만들 때 어디서 막히는가 |
| D4–5 | 들어온 질문에 직접 답변, 반복 질문 기록 | 다운로드·설치·계정 연결 중 어느 단계가 어려운가 |
| D6 | Threads 후속 2: 원본 보존 원칙 | 개인 체크와 Jira 상태의 차이가 이해되는가 |
| D7 | 자발적으로 체험한 사람에게 다음 날 사용 여부 질문 | 다음 날에도 데일리를 열었는가 |
| D8–10 | 가장 빈번한 문제 하나 개선 후 재검증 | 개선이 실제 불편을 해결했는가 |
| D11 | 실제 개선이 있을 때만 후속 글 게시 | 사용자 피드백이 어떻게 반영됐는가 |
| D12–14 | 반응과 체험 결과 정리, 다음 홍보 주제 결정 | 다시 찾는 기능은 무엇인가 |

D11 글에 쓸 개선이 없다면 사용 팁을 올린다. 사용자 수·성과·후기를 만들어 채우지 않는다. 사용자 말을 인용할 때는 공개 인용 동의를 받는다. 관련 없는 게시글에 링크를 반복하거나 대량 DM을 보내지 않는다.

## 이미지와 데모 준비

첫 게시에는 실제 제품 화면 1장 또는 20–30초 사용 영상을 권한다. 이번 산출물에는 새 이미지나 영상이 포함되지 않는다.

촬영 순서:
1. 연결과 자동 갱신이 설정된 데모 계정에서 시작한다.
2. ‘오늘 데일리 열기’를 누른다.
3. 오늘 일정과 Jira 담당 업무가 모이는 모습을 보여준다.
4. 항목 하나를 체크하고 구역 밖에 개인 기록을 적는다.
5. 같은 데일리를 다시 열어 체크와 기록이 유지되는 모습을 보여준다.

로그인 설정 시간은 데모와 별개다. 연결이 처음부터 필요 없거나 OAuth JSON 없이 Google 로그인이 된다는 인상을 주지 않는다. 계정 이메일·토큰·회사 이슈 제목·내부 URL이 보이지 않는 가상 일정과 테스트 업무를 사용한다. 데모 데이터라면 화면 설명에도 ‘사용 예시’라고 쓴다.

## 측정과 판단

첫 실험 목표 예시: 실제 체험 5명, 그중 다음 날 재사용한 사람 3명. 외부 벤치마크가 아닌 작은 내부 목표다.

| 지표 | 확인 방법 | 해석 |
| --- | --- | --- |
| 관심 | 각 플랫폼에서 제공하는 조회·댓글·저장 등 사용 가능한 지표 | 설치나 실제 사용으로 간주하지 않는다 |
| 첫 사용 | 자발적으로 알려 준 설치·데일리 생성 완료 건수 | 단계별 이탈 원인도 함께 기록한다 |
| 재사용 | 체험자의 동의하에 다음 날 사용 여부 질문 | 반복해서 쓸 이유가 있는지 확인한다 |
| 장애 | 사용자 제보의 막힌 단계와 오류 내용 | 인증 정보나 회사 업무 내용은 받지 않는다 |

현재 홈페이지에 분석 도구가 없으므로 UTM을 붙이는 것만으로 유입·설치가 자동 측정되지는 않는다. Drive 이동도 DMG 설치와 다르다. 없는 데이터는 ‘미측정’으로 남긴다.

관심은 높은데 설치가 적으면 배포·설치 안내를 개선한다. 설치 후 연결에서 막히면 OAuth 설정과 토큰 안내를 먼저 개선한다. 첫 사용은 되는데 재사용이 없다면 새 기능 홍보보다 다음 날 다시 열 이유를 묻는다.

## 사실과 표현 기준

- 버전: MORI 0.8.0, Apple Silicon Mac용 무료 공개 베타.
- 사용자 대화에서 Google Calendar와 Jira 연결 동작이 확인됐다고 보고됐다. 모든 계정·조직에서 검증 완료라는 뜻은 아니다.
- GitHub·GitLab은 구현 및 모의 응답 테스트가 있으나 사용자 실계정 검증은 남아 있다. 첫 홍보의 핵심 성공 사례로 사용하지 않는다.
- 자동 반영은 서비스 연결과 자동 갱신 설정 후 ‘오늘 데일리 열기’ 또는 데일리 생성에서 실행한다. 앱 종료 중 예약 실행이나 모든 메모 선택 시 갱신이 아니다.
- Google은 데스크톱 OAuth JSON, Jira Cloud는 사이트·이메일·일반 API 토큰 설정이 필요하다.
- 메모는 로컬 Markdown이다. 외부 일정 조회와 AI 처리까지 오프라인이라는 뜻은 아니다.
- MORI 체크는 개인 기록이다. Jira 이슈 상태를 바꾸지 않는다.
- Developer ID 서명·공증 전 베타다. 설치 제한을 모든 Mac에서 같은 방법으로 해결할 수 있다고 보장하지 않는다.
- 무료 앱과 외부 AI 제공자 비용은 구분한다.
- Codex·Claude 스킬은 문서 검색·읽기를 연결한다. 임베딩 기반 RAG나 저장소 전체 자동 이해로 과장하지 않는다.

## 참고한 플랫폼 공식 안내

- [Meta: Threads 교육 안내](https://about.fb.com/news/2024/10/find-your-community-with-new-threads-educational-insights/)는 Threads에 맞는 독창적인 콘텐츠와 대화를 강조한다. 이에 맞춰 질문 중심의 짧은 글을 제안했다.
- [Meta: Threads 링크와 Insights](https://about.fb.com/news/2025/03/new-threads-features-more-personalized-experience-you-control/)는 링크와 게시물 반응을 살펴볼 도구를 소개한다. 사용 가능한 지표만 기록한다.
- [LinkedIn: Thought Leadership 콘텐츠](https://www.linkedin.com/business/marketing/blog/content-marketing/creating-a-thought-leadership-marketing-plan)는 개인의 관점과 일관된 메시지를 설명한다. 제작자의 문제 정의와 설계 선택을 담았다.

게시 빈도·실험 목표·채널 배분은 MORI를 위한 제안이다. 알고리즘 보장이나 업계 평균으로 제시하지 않는다. 벨로그 구성은 개발 기록을 읽는 독자에게 맞춘 편집 판단이며 플랫폼 노출 규칙을 주장하지 않는다.
