# 데일리 업무 모음 개발 계획

## 합의한 방향
데일리를 오늘 일정·할 일·기록의 중심으로 사용한다. 같은 날짜의 데일리는 재사용하며 제목·폴더를 바꿔도 날짜 식별자를 유지한다. 외부 서비스는 사용자가 계정, 캘린더/프로젝트, 담당자·상태·기한 조건을 선택해서 연결한다.

## 단계
1. 로컬 데일리: 오늘 노트 재사용, 메모의 미완료 체크리스트 선택 전송, 직접 할 일 입력, 원본 ID 링크, 지난 데일리의 미완료 항목 선택 이월.
2. Google Calendar: OAuth 데스크톱 클라이언트 설정 후 읽기 전용 연결, 캘린더 선택, 오늘 일정 가져오기. 실제 계정 연결 검증 필요.
3. Jira, GitHub, GitLab: 각 서비스별 인증과 조회 조건을 제공하고 데일리에 연결.

## 데이터와 보존
- 메모 frontmatter에 dailyDate와 dailyTaskKeys를 기록한다. 기존 날짜 제목의 데일리는 최초 접근 때 식별자를 부여한다.
- 전송은 보관함 저장 큐에서 실행한다. 원본 revision 검증 후 최신 데일리에 추가하고 기존 본문과 저장 이력을 보존한다.
- 오늘의 날짜는 Mac 로컬 날짜다. 같은 날짜 후보가 여럿이거나 휴지통에 있으면 자동 생성하지 않고 해결 안내를 한다.
- 할 일은 Markdown 체크박스로 저장한다. 출처 ID 링크와 숨김 출처 키를 유지한다.
- 같은 원본의 같은 내용·출현 순서 기준으로 중복을 방지한다. 같은 이름의 다른 메모는 구분한다. 원문 텍스트 변경은 새 항목으로 취급한다.
- 데일리에서 체크해도 원본 체크박스는 변경하지 않는다. 이월도 원본을 남긴다.
- 숨김 표식을 사용자가 삭제하면 이월 시 원래 출처 식별이 끊길 수 있다. 전송 기록 키는 삭제된 항목의 자동 재생성을 방지한다.

## 외부 연동 공통 계약
연결별 provider/account/container/remoteId/occurrenceId를 조합해 항목을 식별한다. 반복 일정은 발생 회차별로 구분한다. provider 상태와 MORI 체크 상태를 별도로 보관한다. 메모 본문 전체를 외부 응답으로 덮어쓰지 않는다.
사용자가 추가한 기록, 과거 데일리, 취소된 원본의 마지막 상태를 보존한다. 오류·오프라인 시 마지막 성공 데이터와 갱신 시간을 표시한다. 취소·삭제·이동은 중복 생성 대신 상태로 반영한다.
인증 토큰은 메모/백업/로그에 넣지 않고 OS 암호화 저장소를 사용한다. 첫 단계는 읽기 전용이며 외부 일정·이슈 수정은 별도 기능이다.

## 완료 기준
동시 클릭·재시작·이름 변경·중복·충돌·미완료 이월·원본 보존을 임시 보관함으로 검증한다. 외부 연동은 실제 로그인/선택/조회/취소/재인증까지 검증한 뒤 연결 가능으로 표시한다.
