# 앱 없이 읽는 문서 공유 · PDF·HTML·웹 링크

2026-10-21 구현. 메모와 보고서의 PDF·HTML 내보내기는 서버 없이 동작한다. 웹 공유 코드는 기존 계정 API에 연결했으며 실제 외부 링크 제공에는 서버 배포·Supabase 설정이 필요하다. 기본 무료 베타는 계정·서버 연결 없이 파일 내보내기를 사용한다.

## 사용법

메모 위 **공유·내보내기**, 보고서 초안의 **PDF·HTML·웹 공유**를 누른다. 공유 창은 버튼을 누를 때 읽은 문서 복사본을 미리 보여준다. 편집 중인 메모는 먼저 저장하며 원본 파일은 변경하지 않는다.

- **PDF로 내보내기:** A4 문서를 만든다. 메일·메신저 첨부나 보고서 제출에 사용한다.
- **HTML로 내보내기:** 스타일을 포함한 단일 HTML 파일이다. 받는 사람이 브라우저로 열 수 있고 인터넷 연결·MORI 설치가 필요하지 않다.
- **공유 링크 만들기:** 계정이 연결된 상용 빌드에서 사용한다. Pro 또는 무료 체험 계정으로 로그인하고 공개될 복사본 업로드에 동의한 뒤 만든다. 링크를 받은 사람은 설치·가입 없이 읽는다.
- **공유본 업데이트:** 원문 수정은 자동 반영되지 않는다. 공유 창을 다시 열고 현재 미리보기를 확인한 뒤 업데이트한다. 기존 URL은 유지한다.
- **공유 중단:** 서버의 공개 본문을 지우고 기존 URL을 404로 전환한다. 이미 내려받은 파일·복사본·스크린샷을 회수하지는 못한다.
- **다시 공유:** 중단된 문서를 새로 공개하면 새 URL을 발급한다. 이전 URL은 다시 살아나지 않는다.

원본 메모를 삭제했거나 Pro 이용 기간이 끝나도 **설정 → 계정 및 Pro → 공유 문서 관리 → 공유 문서 목록 불러오기**에서 공개된 문서를 확인하고 중단할 수 있다. 로그인은 필요하지만 활성 Pro 권한은 필요하지 않다.

## 공개 범위와 한도

| 항목 | 첫 버전 동작 |
|---|---|
| 파일 내보내기 | Free·Pro 모두 가능 |
| 웹 생성·업데이트 | 서버에서 현재 Pro/체험과 등록 기기 확인 |
| 웹 상태 확인·중단 | 로그인한 작성자. 만료 후에도 가능 |
| 받는 사람 | 링크만으로 읽기. 편집·댓글·앱 설치 불필요 |
| 공개 범위 | 선택한 문서의 제목·본문 복사본 한 장 |
| 연결·외부 링크 | 표시 글자만 남김. 대상 주소·문서 ID·연결된 원문은 보내지 않음 |
| 이미지·첨부 | 파일을 읽거나 업로드하지 않고 제외 표시 |
| HTML·숨겨진 주석·각주 정의 | 공유용 본문에서 제외 |
| 코드 블록·인용문 | 현재 문서에 실제 적힌 내용이므로 포함 |
| 분량 | 입력과 정리된 본문 각각 최대 100,000자. 초과 시 줄이도록 안내 |
| 웹 한도 | 계정당 활성 링크 20개. 중단하면 슬롯을 다시 사용 |
| 구독 종료 | 새 생성·업데이트 제한. 기존 공개본은 작성자가 중단할 때까지 유지 |

‘원문 모음’ 보고서에 이미 복사해 넣은 다른 메모의 본문은 보고서 내용이므로 공유된다. 연결된 문서를 별도로 찾아 추가하는 동작은 하지 않는다. 미리보기에 보이는 내용을 기준으로 확인한다.

웹 링크는 비밀번호나 지정 수신자 인증이 없는 **링크 소지자 공개** 방식이다. 다른 사람에게 전달될 수 있다. 검색 색인·캐시를 거부하는 헤더와 robots 지침을 제공하지만 모든 외부 서비스의 수집·복사를 막는다고 보장하지 않는다. 비밀번호, 만료 시간, 이미지 첨부, 댓글과 공동 편집은 이번 범위에 없다.

## 구현

- `shared/share-document.tsx`: Markdown을 파싱해 공개 가능한 표시 내용만 남긴다. 표·체크리스트·코드·제목을 유지하고 내부 참조·이미지·HTML·링크 목적지를 제거한다. 앱과 서버가 같은 처리를 반복해도 결과가 바뀌지 않게 검증한다.
- `electron/sharing/sharing-service.ts`: 미리보기마다 변경되지 않는 복사본을 보관한다. 내보내기와 업로드는 그 복사본만 사용한다.
- `electron/sharing/export.ts`: HTML 저장과 격리된 숨김 Electron 창의 PDF 출력을 처리한다. 출력 창에는 preload·Node 접근이 없고 외부·로컬 파일 요청을 차단한다.
- `server/sharing/service.ts`: Pro 확인, 작성자 관리, 공개 읽기. 공개 HTML에는 작성자 ID·이메일·보관함 경로를 넣지 않는다.
- `server/billing/migrations/002_sharing.sql`: 소유자 잠금으로 한도·중복 생성·수정 충돌을 처리하고 DB의 클라이언트 역할 접근을 제한한다.
- `src/app/ShareDialog.tsx`: sandbox iframe으로 결과를 보여주고 업로드 동의를 받는다.

공개 주소는 긴 무작위 토큰을 사용한다. HTML은 스크립트·이미지·외부 요청·폼을 막는 CSP, no-store, noindex/nofollow/noarchive, no-referrer, 프레임 삽입 거부 헤더를 사용한다. 작성자 목록·수정·중단 API는 인증한 사용자로 한정한다. 공개 읽기에는 사용자 로그인·쿠키·메모 보관함 접근이 필요하지 않다.

생성 요청이 중복되면 기존 활성 공유본을 반환하며 조용히 업데이트하지 않는다. 수정은 revision을 검사한다. 중단은 본문을 지우며 재공개는 공개 토큰을 교체한다. 계정 변경·로그아웃 시 이전 계정의 관리 목록을 화면에 유지하지 않는다.

기존의 ‘계정·결제 API에는 메모 본문을 보내지 않음’ 원칙에 명시적 공유 경로를 추가한다. **사용자가 웹 공유를 선택하고 동의한 복사본만** `/shares` 경로로 전송한다. 로그인·결제·파일 내보내기만으로는 메모를 업로드하지 않는다.

## 서버 연결과 검증

이미 계정 서버 DB에 `001_billing.sql`을 적용했다면 `002_sharing.sql`만 추가 적용한다. 새 프로젝트는 둘을 순서대로 적용한다. 추가 공급자 키 없이 기존 Supabase·계정 서버를 사용한다. [계정 서버 운영 연결 가이드](billing-implementation.md)를 따른다.

```sh
npm test
npm run build
npm run build:billing
node scripts/billing-db-smoke.mjs
node scripts/sharing-smoke.mjs
```

단위 테스트는 숨겨진 내용·링크 목적지 제외, HTML 무력화, 서버 재검증 동일성, 업로드 동의, 소유자 격리, Pro 만료, 한도, 중단·재발급을 검사한다. DB 검증은 실제 임시 PostgreSQL에서 migration·동시 수정·중복 생성·본문 삭제·URL 교체·권한·한도를 확인한다.

앱 검증은 임시 보관함과 로컬 테스트 서버에서 실제 HTML·PDF를 만들고 비로그인 읽기, 원본 수정의 비자동 반영, 업데이트·중단, 재공개, 원본 삭제 후 관리 화면의 중단을 확인한다. 실제 운영 URL을 인터넷에 공개한 검증은 아니다.
