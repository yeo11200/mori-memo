# MORI 다음 개발 계획

> 다음 작업 때 이 문서부터 확인한다. 현재 범위는 macOS 앱이며, 아이폰 앱은 동기화 방식이 정해진 뒤 시작한다.

## 유료화 확장 후보 · 2026-09-15

계정 방향은 [이메일 계정·결제 계획](account-billing-plan.md)을 따른다. 무료 사용은 로그인 없이 제공하고, Pro 구매는 고유 사용자 ID에 연결한다. 동기화·팀은 동일 계정 위에 별도 구현한다.

[유료 기능 아이데이션](paid-feature-ideas.md)에 앱 기능 20개와 Codex·Claude/AI 기능 8개를 정리했다. 권장 순서는 미완료 이월·연결 진단 → 주간보고·템플릿 체험 → 수요 검증 후 과금이다. 신규 기능은 계획 상태이며 기존 구현 기록과 구분한다. 앱과 AI 스킬을 별도 영역으로 개발하고, 가격과 출시 범위는 아직 확정하지 않았다.

## 2일차 구현 · 2026-09-08

아래 기능을 구현했다. 검증 및 남은 범위는 [day2-implementation.md](day2-implementation.md)에 기록한다.

1. 연결 대상 메모를 폴더별로 정리할 수 있도록 폴더 모델과 사이드바를 추가한다.
2. `[[문서]]` 링크의 자동완성 목록에 폴더 경로를 함께 표시한다.
3. 폴더를 이동해도 문서 ID와 링크는 유지한다. 제목이 바뀌면 이전 제목을 alias로 남긴다.
4. 폴더별 메모 수, 현재 폴더 필터, 폴더 생성·이름 변경·삭제를 구현한다.
5. 폴더 삭제 시 문서를 지우지 않고 `미분류`로 이동한다.
6. 설정의 모델 입력칸을 선택 목록으로 바꾼다. Codex는 `gpt-5.6-luna`를 기본 선택으로 두고, 사용할 수 없는 모델은 목록에서 숨기거나 상태를 표시한다.
7. 캡처·빠른 메모 단축키를 문자열 입력이 아니라 실제 키 조합 녹화 방식으로 바꾼다. 입력칸을 누른 뒤 `⌘⇧2`처럼 누르면 `CommandOrControl+Shift+2`로 정규화해 보여준다.
8. 단축키 녹화 중 `Delete`는 해제, `Escape`는 취소로 동작하게 한다. 저장 전에 충돌 여부를 검사하고 등록 실패 이유를 보여준다.
9. 단축키와 동작을 한 쌍으로 커스텀할 수 있게 한다. 사용자가 `캡처`, `빠른 메모`, `검색`, `새 메모`, `AI 초안` 같은 동작을 선택하고 각각 원하는 조합을 지정한다.

## 폴더와 연결 구조

```text
Vault/
  Notes/                 # 메모 본문과 안정적인 문서 ID
  Attachments/           # 캡처와 이미지
  .wiki/
    history/             # 문서별 버전
    trash/               # 복원 가능한 삭제 문서
    results/             # AI 결과
    settings.json
    folders.json         # 빈 폴더를 포함한 목록
```

폴더는 파일 경로의 의미와 분리된 메타데이터로 관리한다. 메모 파일은 현재처럼 ID를 파일명으로 사용해 이동·이름 변경에도 링크를 보존한다. 폴더 링크는 `[[폴더/문서]]` 형식으로 표시하고, 실제 해석은 ID·제목·alias를 기준으로 한다.

## Obsidian에서 참고할 점

참고할 핵심은 기능의 양보다 작성 흐름이다.

- Markdown 파일을 그대로 보관해 사용자가 언제든 열 수 있게 한다.
- `[[위키링크]]`, 백링크, 그래프 뷰로 생각의 맥락을 보여준다.
- 폴더는 큰 분류에만 쓰고, 세부 관계는 링크와 태그로 표현한다.
- 명령 팔레트는 동작·사용자 AI 명령만 제공한다. 문서 탐색은 별도의 검색창·사이드바·그래프에서 한다.
- 원문 편집과 미리보기를 쉽게 오가며, 자동 저장 상태를 항상 보여준다.

MORI는 여기에 AI 결과를 원문과 분리해 확인하고 적용하는 단계를 둔다. AI가 원문을 조용히 덮어쓰지 않도록 하는 것이 차별점이다. Obsidian의 플러그인 생태계나 화면을 그대로 복제하지 않고, 개인 메모와 AI 정리에 필요한 부분만 가져온다.

## AI 제공 방식 두 가지

설정에서 `로컬 기반 Codex CLI`와 `원격 API 직접 연결`을 선택할 수 있게 한다. 두 방식은 같은 AI 작업 인터페이스를 사용한다.

| 방식 | 실행 방식 | 장점 | 단점 | 1차 구현 |
|---|---|---|---|---|
| 로컬 기반 Codex CLI | 맥에서 `codex exec` 명령 실행 | 현재 사용 흐름 유지, 앱에 API 키를 넣지 않음 | Codex 인증·네트워크 상태 필요 | 현재 방식 |
| 원격 API 직접 연결 | 앱이 API 엔드포인트 호출 | 앱에서 모델 선택 | API 키와 네트워크 필요 | OpenAI 구현 |

현재 Codex 방식은 맥에서 `codex exec --model gpt-5.6-luna`를 실행하는 로컬 기반 CLI 연동이다. 명령과 보관함 접근은 로컬 앱이 담당하고, Codex 모델 추론은 Codex 서비스에서 수행된다. 이것을 현재 기본 방식으로 유지한다. 원격 API 직접 연결은 별도 provider로 추가한다.

Ollama 같은 완전 오프라인 LLM은 위 두 방식과 다른 세 번째 확장 후보다. 기본 옵션으로 섞지 않고, 나중에 별도 provider로 추가한다.

### 모델 선택 UI

사용자가 모델 ID를 직접 오타 내지 않도록 provider에 따라 `<select>` 목록을 보여준다. Codex 목록에는 `gpt-5.6-luna`를 “저비용·빠른 정리”로 표시하고, 필요하면 Terra·Sol을 추가한다. 현재 계정에서 모델을 사용할 수 없는 경우 저장은 허용하되 실행 시 원인을 안내한다. 커스텀 모델 ID가 필요한 고급 사용자를 위해 나중에 “직접 입력”을 접힌 고급 옵션으로 둘 수 있다.

### 단축키 녹화 UI

단축키 입력칸은 일반 텍스트 필드가 아니라 recorder다. 포커스를 받은 상태에서 실제 키 이벤트를 조합해 표시하고, macOS 표기는 `⌘`, `⌥`, `⌃`, `⇧`로 보여준다. 내부 저장값은 Electron globalShortcut 형식으로 유지한다.

`⌘Space`는 macOS Spotlight가 기본으로 사용하는 조합이므로 기본값으로 지정하지 않는다. 사용자가 선택하면 등록 시도 후 충돌 메시지를 표시하고, Spotlight를 바꾸지 않도록 안내한다. 캡처 단축키는 누르면 앱을 잠시 숨긴 뒤 화면 선택을 시작하고, 빠른 메모 단축키는 새 빈 메모를 연다.

### 사용자 동작 매핑

단축키 설정은 고정된 두 개의 입력칸이 아니라 동작 목록으로 만든다.

```text
⌘⇧2  → 화면 캡처
⌘⇧N  → 빠른 메모
⌘K   → 검색창 열기
⌘⇧A  → AI 초안 작성
```

각 행에서 동작을 바꾸거나 단축키를 다시 녹화한다. 같은 동작에 여러 단축키를 등록하는 것은 허용하고, 한 단축키를 두 동작에 연결하는 것은 막는다. 기본 제공 동작 외에 사용자가 저장한 AI 명령을 “사용자 동작”으로 추가할 수 있게 하며, 단축키 없이 메뉴와 명령 팔레트에서도 실행할 수 있어야 한다. 앱 내 단축키와 전역 단축키는 구분해 표시한다.

공통 인터페이스는 다음처럼 유지한다.

```ts
interface AIProvider {
  handleRun(request: AIRequest): Promise<string>;
  handleCancel(): void;
  handleCheck(): Promise<{ ready: boolean; label: string }>;
}
```

메모 본문은 AI 실행을 요청할 때만 전송한다. 로컬 기반 Codex CLI는 설치된 CLI 인증을 사용하고, 원격 API 직접 연결은 앱에서 API 키를 설정한다. 두 방식 모두 모델 추론은 외부 서비스에서 수행한다.

## 추가 아이디어

- 메모 템플릿: 회의록, 독서 기록, 일일 로그, 아이디어, 프로젝트 회고
- 오늘의 빠른 캡처를 임시 보관한 뒤 나중에 메모로 승격
- AI 작업 기록과 이전 결과 비교, 결과를 새 문서로 저장
- 태그 자동 제안과 태그별 색상
- 제목 없는 메모를 하루 뒤 한 번만 정리하라고 알려주는 리마인더
- 그래프에서 폴더·태그·문서 유형별 필터
- 로컬 검색은 SQLite FTS로 확장하고, 임베딩은 명시적으로 켠 경우에만 사용
- 아이폰은 iCloud Drive 또는 선택한 동기화 폴더를 기반으로 먼저 오프라인 편집을 지원
- 충돌 시 자동 병합하지 않고 두 버전을 나란히 보여주기
- 내보내기 전에 링크가 끊긴 문서를 검사하는 건강성 리포트

## 우선순위

2026-09-08: [폴더 중심 그래프](folder-graph.md)를 0.2.1에 구현했다. 폴더 집계 → 내부 문서 → 참조 상세 탐색을 지원한다. 하위 폴더 트리와 물리 배치는 후속 작업이다.

`폴더와 링크 자동완성 → AI 제공자 선택 → 명령 팔레트 → 아이폰 동기화 → 검색 인덱스와 그래프 고도화` 순서로 진행한다. 각 단계는 기존 Markdown 파일과 문서 ID를 깨뜨리지 않는 것을 완료 조건으로 한다.

## 확인할 질문

모델 목록은 앱 카탈로그이며 계정 권한을 자동 조회하지 않는다. 연결 확인 및 실행 오류로 사용 가능 여부를 안내한다. 실제 원격 API 호출은 사용자 키로 확인해야 한다.

- 완전 오프라인 모델은 현재 2일차 범위에 포함하지 않는다.
- 아이폰 동기화를 iCloud Drive 기반으로 시작할지, 작은 동기화 서버를 둘지
- 폴더를 한 단계만 허용할지, 여러 단계의 하위 폴더를 허용할지
