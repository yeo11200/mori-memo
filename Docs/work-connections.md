# Jira·GitHub·GitLab 담당 업무 연동 (MORI 0.8.0)

## 사용하기

1. MORI **설정 → 담당 업무 → 오늘 데일리**에서 서비스를 펼칩니다.
2. 계정 정보를 입력하고 **연결**을 누릅니다. 실제 계정 확인과 담당 업무 조회가 모두 성공해야 연결됨으로 표시합니다.
3. **원본 상태**에서 미완료 또는 완료 포함 전체를 선택합니다.
4. 모든 프로젝트를 가져오거나 체크를 해제한 뒤 원하는 프로젝트만 선택합니다.
5. **필터 저장·오늘 업무 가져오기**를 누르면 오늘 데일리에 반영합니다.
6. **오늘 데일리 열 때 자동 갱신**을 켜고 필터를 저장하면 사이드바의 오늘 데일리 열기·데일리 생성 메뉴에서 갱신합니다.

앱을 닫은 동안 예약 실행하거나, 일반 메모 목록에서 기존 데일리를 선택할 때 갱신하지 않습니다. 프로젝트 선택이 비어 있으면 새 업무를 추가하지 않습니다. 연결 해제는 이 Mac의 토큰을 지우며 기존 데일리는 남습니다.

## 서비스별 준비

| 서비스 | 입력 | 지원 범위 |
| --- | --- | --- |
| Jira | Jira Cloud 사이트 주소, 계정 이메일, 일반 API 토큰 | 내 담당 이슈, 프로젝트, 원본 상태, 기한 |
| GitHub | Personal access token | GitHub.com의 내 담당 Issues, 저장소, open/closed 상태 |
| GitLab | read_api 권한 Personal access token | GitLab.com의 내 담당 Issues, 프로젝트, 상태, 기한 |

### Jira Cloud

사이트는 **https://회사.atlassian.net** 형태로 입력합니다. 경로·포트·로그인 정보를 포함한 URL은 허용하지 않습니다.

[Atlassian API 토큰 관리](https://id.atlassian.com/manage-profile/security/api-tokens)에서 일반 API 토큰을 준비합니다. 이메일과 토큰을 사용하는 [Basic 인증](https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/) 방식입니다. 범위 지정 토큰의 별도 api.atlassian.com 경유 방식, Jira Data Center는 이번 버전에 포함하지 않았습니다.

내 계정에 배정된 업무만 조회합니다. 미완료 조건은 statusCategory != Done이며, 조회 권한이 없는 프로젝트·이슈는 가져올 수 없습니다.

### GitHub.com

[GitHub 토큰 관리](https://github.com/settings/tokens)에서 토큰을 준비합니다. Fine-grained 토큰은 필요한 대상 저장소에 접근하도록 설정하세요. 조직의 승인·SSO·토큰 정책에 따라 조회 범위가 제한될 수 있습니다. Classic 토큰으로 비공개 저장소를 읽으려면 repo 범위가 필요합니다.

현재 사용하는 [담당 이슈 API](https://docs.github.com/en/rest/issues/issues#list-issues-assigned-to-the-authenticated-user)는 Fine-grained 토큰도 지원합니다. 실제 반환 범위는 토큰과 계정의 접근 권한에 따릅니다. MORI는 읽기 요청만 전송하지만 Classic repo 토큰 자체에는 더 넓은 권한이 있을 수 있습니다.

Pull Request, GitHub Projects의 초안·보드 항목, GitHub Enterprise는 제외합니다. Issues에는 공통 기한 필드가 없어 기한을 임의로 만들어 넣지 않습니다.

### GitLab.com

[GitLab Personal access tokens 안내](https://docs.gitlab.com/user/profile/personal_access_tokens/)에 따라 **read_api** 권한 토큰을 만듭니다. 프로젝트 토큰·그룹 토큰이 아닌 사용자 토큰을 사용하세요. 현재 사내 설치형 GitLab과 보드 자체의 동기화는 지원하지 않습니다.

[Issues API](https://docs.gitlab.com/api/issues/)에서 scope=assigned_to_me로 조회합니다.

## 기록을 보존하는 규칙

- 오늘의 날짜는 Mac 로컬 날짜이며 같은 날짜의 데일리를 재사용합니다. 데일리의 제목이나 폴더를 바꿔도 다시 만들지 않습니다.
- 서비스·계정·Jira 사이트를 조합한 출처와 원본 이슈 ID로 갱신합니다. 같은 이슈를 반복해서 가져와도 새 줄을 추가하지 않습니다.
- 체크박스는 MORI의 개인 완료 표시입니다. 원본의 open/closed/진행 중 상태는 별도 텍스트이며 체크가 원본으로 전송되지 않습니다.
- 다음 날짜의 데일리는 새 체크 상태로 시작합니다. 외부 업무는 서비스에서 다시 조회하므로 수동 미완료 이월 목록에서 제외합니다.
- 조회에서 빠진 기존 업무는 마지막 내용을 남기고 **조회 대상에서 제외됨**으로 표시합니다. 담당자·필터·권한 변경, 완료·삭제 등을 조회 부재만으로 구분할 수 없으므로 삭제나 완료로 단정하지 않습니다.
- 프로젝트 목록에는 지금까지 조회한 담당 업무의 프로젝트가 표시됩니다. 접근 가능한 모든 프로젝트 목록은 아닙니다.
- 기존 계정의 데일리와 다른 계정의 업무는 별도 구역입니다. 계정을 바꾸려면 연결 해제 후 새 토큰으로 연결하세요.
- 과거 데일리와 가져온 구역 밖의 개인 기록은 갱신하지 않습니다.
- 가져온 구역의 **체크 이외의 내용**을 직접 수정하거나 구역을 삭제하면 해당 서비스 갱신을 거부합니다. 버전 기록으로 구역을 복원한 뒤 다시 가져오세요.
- 모든 페이지 조회가 성공한 뒤 해당 서비스의 결과를 저장 큐에서 적용합니다. 실패·인증 만료·호출 제한·잘못된 응답이면 해당 서비스의 기존 기록을 유지합니다. 서비스별 작업은 독립적이므로 다른 서비스의 성공한 반영은 유지됩니다.
- 최대 100페이지(페이지당 요청 100건)를 조회합니다. 한도를 초과하면 일부 결과만으로 기존 기록을 변경하지 않습니다.

## 보안과 저장 구조

토큰은 보관함 밖 **Secrets/work-connections.bin**에 Electron safeStorage로 암호화해 저장합니다. 암호화를 사용할 수 없으면 평문 저장으로 대체하지 않습니다. 렌더러로 돌려주는 연결 상태에는 토큰이 없고, 메모·메모 백업에도 토큰을 넣지 않습니다.

인증 요청은 고정 서비스 주소와 검증한 Jira Cloud 사이트로만 보냅니다. 인증정보가 리다이렉트로 전달되지 않도록 리다이렉트를 거부합니다. API 오류 본문을 그대로 화면이나 로그에 출력하지 않습니다.

메모 frontmatter의 workSnapshots에는 출처·업무의 마지막 내용·갱신 시간·렌더링한 구역을 저장합니다. 본문의 숨김 표식을 포함해 중복 갱신과 직접 편집 충돌을 검사합니다. 미리보기·목록 요약에서 표식을 숨겨도 체크박스 원본 행 번호는 유지됩니다.

## 검증과 남은 범위

2026-09-15 확인: 전체 106개 자동 테스트, 개발 앱 및 Apple Silicon 0.8.0 패키지의 업무 연동 화면 검증, 패키지의 Google Calendar 회귀 검증을 통과했습니다.

- 자동 테스트: 세 서비스 응답 변환, 인증 실패·기존 연결 보존, 페이지 실패·순환 방지, 프로젝트 필터, 자동 갱신 설정, 체크 보존, 중복 방지, 직접 수정 충돌, 재시작·이름/폴더 변경, 날짜 변경, 안전한 링크.
- Electron 동작 검증: 임시 보관함에서 세 서비스의 폼·프로젝트 선택·가져오기·체크 저장·자동 갱신·연결 해제. 실제 서비스와 Vault 로직을 사용하고 **외부 HTTP 응답만 모의 데이터**로 대체합니다.
- 실제 사용자 계정의 로그인·권한·조직 정책·실데이터 조회는 아직 미검증입니다. 앱의 연결 입력에서 본인 토큰으로 확인해야 합니다.
- 이번 범위는 **내 담당 업무 + 프로젝트 + 원본 상태**입니다. 다른 담당자 선택, 기한 필터, 커스텀 JQL·라벨, 사내 설치형 서비스, 외부 원본 수정은 후속 범위입니다.
- Google Calendar는 기존 OAuth 데스크톱 JSON 등록이 필요합니다. 이번 작업이 Google 로그인 설정을 대신 완료하지는 않습니다.
