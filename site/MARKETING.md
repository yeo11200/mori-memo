# MORI 홍보 사이트 메시지와 전환 설계

## 핵심 메시지
“쌓아 둔 메모를, 다시 쓰는 지식으로.”
기능 이름보다 사용자가 얻는 결과를 먼저 제시한다. “어딘가 적어 둔 생각을 다시 찾기 어렵다”는 구체적 상황에 공감하고, 연결과 재사용을 해결 방법으로 보여준다.

## 방문자 흐름
1. 문제 공감과 이익: 첫 화면에서 개인 위키의 쓰임을 설명한다.
2. 제품 근거: 실제 MORI 화면을 크게 배치한다. 이미지는 별도 탭에서 원본 크기로 열 수 있다.
3. 사용 장면: 결정 배경 찾기, 작업 중 기록하기, Google Calendar와 Jira·GitHub·GitLab 업무를 오늘 데일리에 모으기, 필요할 때 AI로 정리하기.
4. 시작 비용 줄이기: Apple 메모 가져오기 3단계 안내.
5. 대상별 메시지: 일반 메모 사용자는 기록 재발견, 개발자는 Codex·Claude의 문서 기반 작업을 강조한다.
6. 신뢰와 우려 해소: 로컬 보관, 외부 AI 처리 범위, 지원 환경, 비용, 가져오기 제약, 서명·공증 상태를 설명한다.
7. 행동 유도: 상단·첫 화면·마지막에서 동일한 무료 베타 안내로 이동한다.

## 카피와 디자인
- 하늘색·흰색과 실제 MORI 새싹 로고를 사용한다.
- 개발자 영역은 짙은 남색으로 구별하되 같은 제품의 활용 방식임을 유지한다.
- 기능 개념도와 AI 요청 예시는 “예시”로 표시한다. 실제 앱 캡처와 혼동시키지 않는다.
- 가짜 후기, 사용자 수, 다운로드 수, 희소성이나 성과 수치는 사용하지 않는다.
- 신규 의존성, 추적 코드, 외부 폰트 요청 없이 정적 파일로 제공한다.

## 다운로드 공개
Drive 공개 URL 확인 전에는 준비 중으로 표시한다. 일반 Google Drive 홈페이지를 다운로드로 연결하지 않는다.
공개 링크를 받은 뒤 config.js의 downloadUrl 한 곳에 입력하고, 로그아웃 상태에서 실제 접근 가능 여부를 확인한다.
앱 사용 무료와 외부 AI 비용은 구분한다.
외부 연동은 원본을 수정하지 않고 읽어 오늘 데일리에 정리하는 흐름으로 설명한다. MORI에서 체크한 상태는 개인 기록이다.

## 배포 이후 검증할 가설
- 일반 사용자에게는 “메모 재발견”, 개발자에게는 “AI가 기준 문서부터 읽기”가 더 이해하기 쉬운 진입 메시지인지 인터뷰한다.
- 설치를 망설이는 이유가 지원 환경인지 macOS 경고인지 피드백으로 구분한다.
- 첫 메모와 첫 연결을 만드는 데 어려움이 있는지 확인한다.
- 전환 지표가 필요해지면 수집 범위와 개인정보 안내를 먼저 정하고 방문 → 다운로드 이동 → 실제 설치를 구분해 측정한다. 현재 사이트에는 분석 도구가 없다.
